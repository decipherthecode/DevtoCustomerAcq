# How to Fill This Document

> **Read this section first before touching anything else.**

---

## 🙋 Who Is This Template For?

This template is for **founders, entrepreneurs, product owners, and builders** who have an idea and want to make sure it solves a *real* problem before spending months or money building it.

**If you're brand new**, that's completely okay. Every section has:
- 📝 **Instructions** — telling you exactly what to write
- 💡 **Example** — showing you a filled-in sample using a fictional product called **"TaskBuddy"** (an app that helps freelancers track their invoices automatically)

---

## 📅 When to Use This Template

Use this template **before you write a single line of code** or spend money on design.

You should fill this out when:
- ✅ You have an idea and want to see if people actually care about the problem
- ✅ You've noticed something broken in the world and want to fix it
- ✅ You want to pitch investors and need proof the problem is real
- ✅ You're starting a new project within an existing company

---

## 🗂️ How to Use This Template

1. **Copy this file** → rename it `Problem_Validation_[YourProjectName]_[Date].md`
2. **Fill every section** — do not skip any, even if it feels hard
3. **Score yourself** honestly at the end using the Go/No-Go rubric
4. **Share it** with a mentor, co-founder, or trusted advisor for feedback
5. **Revisit it** every 2 weeks and update as you learn new things

## 🧪 Section 7: MVP / Prototype Validation

> 📝 **Instructions:** Before building the full product, you should build the smallest possible version to test your core assumption. This is called a Minimum Viable Product (MVP). Your MVP should be ugly, fast, and cheap to build.

---

### 7.1 Core Problem Hypothesis

> 📝 **Instructions:** Write your hypothesis using this formula. This is what your MVP will test.

**Formula:** `We believe [type of user] will [do this action] to solve [this specific problem]. We'll know we're right if [this measurable outcome] happens within [timeframe].`

**Your Hypothesis:**
```
We believe [user type] will [action] to solve [problem].
We'll know we're right if [metric] within [timeframe].
```

> 💡 **Example (TaskBuddy):**
> We believe freelancers will sign up and send at least 1 invoice within 7 days of using a simple, automated invoicing tool. We'll know we're right if 40% of new users send their first invoice within 7 days of signing up.

---

### 7.2 MVP Type Selection

> 📝 **Instructions:** Choose the type of MVP you'll use to test your hypothesis. Pick the cheapest and fastest option that gives you real signal.

| MVP Type | Description | Time to Build | Best Used When |
|----------|-------------|---------------|----------------|
| **Concierge MVP** | You do the job manually, pretending the product exists | 1 day | You need to prove the outcome, not the tech |
| **Wizard of Oz** | Users think it's automated, but you're doing it manually behind the scenes | 1–3 days | You need to test the experience without building the engine |
| **Landing Page MVP** | Build a page that describes the product and captures waitlist signups | 1–3 days | You need to test demand before building |
| **Clickable Prototype** | Design screens in Figma or similar — no real code | 3–7 days | You want feedback on UX / flow |
| **Walking Skeleton** | Build only the single most important feature, bare minimum | 1–4 weeks | You've already validated demand and need a working demo |
